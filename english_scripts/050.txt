SCENARIO 050
版本与接口兼容性

B / Developer: The new API passes our integration tests. Which clients are failing, and do they all receive the same response from the server?

A / Ops Engineer: Clients using the previous response format fail when parsing the result. The server returns success, so the usual server error dashboard misses this impact.

C / Application Lead: How much production traffic still comes from those clients? Can we coordinate an immediate upgrade, or are some versions outside our direct control?

A / Ops Engineer: Older clients account for eighteen percent of requests. Some belong to external partners, and their release schedules mean an immediate upgrade isn't realistic.

B / Developer: We replaced a text status field with a structured object. Our tests covered current clients, but they didn't include the older partner contract.

C / Application Lead: Then we need a compatible mitigation while those clients are updated. Is restoring the old field possible without breaking clients already using the new format?

B / Developer: We can serve the previous format through the existing versioned endpoint. I'll verify that its routing and response behavior still match the documented contract.

A / Ops Engineer: Please check how callers select that endpoint. We should avoid guessing client versions from incomplete headers or sending partners to an untested fallback.

C / Application Lead: I'll have the integration owner confirm the affected client list and contact owners through the established process. What validation do you need before rollout?

B / Developer: Contract tests for both response versions, plus sample calls from an affected partner client. We also need to check that both paths preserve authorization behavior.

A / Ops Engineer: I'll monitor client completion metrics as well as server responses. Let's review the test evidence in twenty minutes before approving the compatibility change.

C / Application Lead: Agreed. I'll own the migration schedule and require confirmed client adoption before we set a retirement date for the older API version.
