# 运维跨国会议｜100个场景对话

按当前已知的“运维工作＋跨国会议”背景编写，面向生产运维、应用运维、基础设施与SRE协作。未提供具体技术栈，因此使用常见企业环境作为示例。全部案例、数据、日期和角色均为模拟；故障等级、审批与恢复要求请替换为所在组织的实际规则。

## 使用方式

- 每组包含：背景、4轮英文对话及中文译文、1个可复用句型、1项落实动作。共100组、400轮双语对话。
- 第一遍理解中文背景并朗读英文；第二遍遮住中文进行角色扮演；第三遍替换服务名、区域、指标和负责人，练习30秒现场回答。
- 建议每天练5组，20天完成一轮。优先练001—010、071—080、091—100，先建立会议沟通、故障响应和跟进闭环能力。
- 跨时区沟通请写清日期与UTC时间，并核对当地时间和夏令时。恢复时间预估与下次更新时间应分开说明。

## 001 介绍职责与支持范围
**分类：** 跨国会议沟通

**背景：** 第一次参加全球运维例会，说明自己的职责。

**你（Ops）：** I support production operations for the APAC region, covering infrastructure, applications, and incident coordination.
> 我负责亚太区生产运维，涵盖基础设施、应用和故障协调。

**同事（Global Lead）：** Do you also own application code changes?
> 应用代码修改也由你负责吗？

**你（Ops）：** The application team owns code changes. I handle operational checks, deployment support, and escalation.
> 代码修改由应用团队负责。我负责运维检查、发布支持和升级协调。

**同事（Global Lead）：** Understood. Please join the weekly service review and flag any regional risks.
> 明白。请参加每周服务评审，并提出区域风险。

**可复用句型：** I handle …, while … owns ….
> 我负责……，而……由……负责。

**落实动作：** 确认责任边界、例会安排和区域风险反馈渠道。

> 失败似乎只影响经过区域网关的请求。

> 不好意思，我没听清最后一部分。能稍微慢一点再说一遍吗？

> 直接请求成功，经过区域网关的请求间歇性失败。

**你（Ops）：** Let me confirm: the issue is intermittent and limited to the gateway path, correct?
> 我确认一下：问题是间歇性的，而且仅限经过网关的链路，对吗？

**可复用句型：** Let me confirm: …, correct?
> 我确认一下：……，对吗？

**落实动作：** 复述影响范围，避免将未听清的信息当作事实。

## 014 磁盘未满但无法写入
**分类：** Infrastructure 基础设施

**背景：** 应用报磁盘已满，但空间监控看起来正常。

**同事（Developer）：** Writes are failing, but the disk still has free space. What are we missing?
> 写入失败，但磁盘还有空间。我们漏查了什么？

**你（Ops）：** The filesystem has run out of inodes because of millions of small temporary files.
> 大量小临时文件耗尽了文件系统的inode。

**同事（Developer）：** Can we clear the temporary directory?
> 能清理临时目录吗？

**分类：** Follow-up 复盘与闭环

**背景：** 亚太值班结束，将未关闭故障交给欧洲团队。

**你（APAC Ops）：** The service is stable after mitigation. Root-cause investigation and backlog reconciliation remain open.
> 缓解后服务稳定，根因调查和积压对账仍未完成。

**同事（EMEA Ops）：** What should we monitor, and when should we escalate?
> 应该监控什么，何时需要升级？

**你（APAC Ops）：** The ticket lists current metrics, escalation thresholds, pending actions, and the next update time.
> 工单列出了当前指标、升级阈值、待办事项和下次更新时间。

**同事（EMEA Ops）：** I've reviewed it and accept ownership. I'll join the next stakeholder update.
> 我已查阅并接手责任，会参加下次干系人更新。

**可复用句型：** I've reviewed the handover and accept ownership from this point.
> 我已查阅交接内容，并从现在起接手责任。

**落实动作：** 交接背景、状态、阈值、待办与沟通节点，并取得接手确认。

## 097 周度运维健康汇报
**分类：** Follow-up 复盘与闭环

**背景：** 全球周会上总结本周稳定性和风险。

**同事（Global Lead）：** What changed in service health this week?
> 本周服务健康状况有什么变化？

**你（Ops）：** Incident count decreased, but total user-impact time increased because of one prolonged outage.
> 故障次数减少，但一次长时间中断使总用户影响时长增加。

**同事（Global Lead）：** What's the main risk for next week?
> 下周主要风险是什么？

**你（Ops）：** The pending capacity action is the main risk. We need a decision on the proposed expansion by Friday.
> 待完成的容量行动是主要风险，需要在周五前决定是否按方案扩容。

**可复用句型：** The main risk is …; the decision needed is … by ….
> 主要风险是……；需要在……前决定……。

**落实动作：** 用统一口径汇报趋势、风险和需要的决定。

## 098 更新Runbook与知识转移
**分类：** Follow-up 复盘与闭环

**背景：** 一次故障暴露操作手册过时，新同事无法独立处理。

**同事（Team Lead）：** The runbook didn't match the current platform. How do we prevent that again?
> 操作手册与当前平台不符，如何避免再次出现？

**你（Ops）：** We'll update the steps, assign a maintainer, and validate them with an engineer unfamiliar with the incident.
> 我们会更新步骤、指定维护人，并请不熟悉该故障的工程师验证。

**同事（Team Lead）：** Please include prerequisites and escalation contacts.
> 请包括前提条件和升级联系人。

**你（Ops）：** I'll also add expected results, stop conditions, and a review date.
> 我还会补充预期结果、停止条件和复查日期。

**可复用句型：** A usable runbook needs clear steps and expected results.
> 可用的操作手册需要清晰步骤和预期结果。

**落实动作：** 通过实际演练验证文档，并明确维护责任和复查日期。

## 099 跨团队责任分歧
**分类：** Follow-up 复盘与闭环

**背景：** 应用和平台团队对复盘行动归属存在分歧。

**同事（Platform Lead）：** This belongs to the application team. We only run the platform.
> 这应该归应用团队，我们只负责运行平台。

**你（Ops）：** Let's separate the platform control from the application behavior and map the actions to each owner.
> 我们把平台控制与应用行为分开，并将行动对应到各负责人。

**同事（App Lead）：** We can own the code fix, but platform support is needed for the detection rule.
> 代码修复可由我们负责，但检测规则需要平台支持。

**你（Ops）：** Agreed. Let's name one accountable owner for each action and document the supporting team.
> 同意。每项行动指定一名最终负责人，并记录支持团队。

**可复用句型：** Let's clarify ownership based on the control that needs to change.
> 我们依据需要改变的控制措施明确责任。

**落实动作：** 将责任讨论落到具体控制、行动和支持关系。

<a id="s100"></a>
## 100 月度复盘与持续改进
**分类：** Follow-up 复盘与闭环

**背景：** 向全球管理层说明改进是否真正有效。

**同事（Director）：** We've closed many action items. How do we know reliability actually improved?
> 我们关闭了很多行动项，如何证明可靠性确实改善？

**你（Ops）：** We'll compare recurrence, detection time, restoration time, and user impact over comparable periods.
> 我们会比较可比周期内的复发情况、发现耗时、恢复耗时和用户影响。

**同事（Director）：** What if the same failure hasn't happened again yet?
> 如果同类故障暂时没有再次发生呢？

**你（Ops）：** We'll use controlled validation and track the limits of the evidence, then prioritize the next improvement.
> 我们会通过受控验证，并说明证据局限，再确定下一项改进优先级。

**可复用句型：** Closure is one milestone; effectiveness needs evidence over time.
> 关闭是一项里程碑，有效性需要随时间积累证据。

**落实动作：** 结合演练和长期指标评估改进效果，形成下一轮优先级。

> 未解决风险：[风险]。下一步：[负责人、动作、UTC截止时间]。
